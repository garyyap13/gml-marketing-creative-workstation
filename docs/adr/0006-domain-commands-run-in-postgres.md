# Domain commands run as Postgres functions, not in an API server

Every state-changing action (submit a Version, approve, request changes, withdraw an approval, create or confirm a Launch, rebrief, write an Optimization Plan, record a Verdict) must check the caller's role, guard against two people acting at once, and write the audit and notification records atomically. For an internal tool of seven people on Supabase, we run each action as a Postgres function called through Supabase RPC, doing the whole check-lock-write-audit-outbox sequence in one transaction, and use Supabase Edge Functions (TypeScript) only for work that calls outside services: the Meta sync and WhatsApp sending. We rejected a separate TypeScript API service, as the TRD and the Video Orchestrator use, because it adds a server to host and an auth layer to maintain; we accept that part of the business logic is written in SQL and tested through integration tests against a local Supabase stack.
